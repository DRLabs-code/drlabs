# 内部研报写法

此文件只给写稿用，不要放到公开站点。

不要套用同一套段落。每个标的自己成篇：先看它到底买的是储备、结算、换手、费用分成，还是注意力。

1. 只写公开数据。记下快照时刻（UTC）和来源（CoinGecko / DefiLlama / LunarCrush / AltIndex / 文档）。
2. 必须对照全网：同行市值与成交、公链 TVL、稳定币、DEX、费用。用对照推出观点，不要复述本币一行快照。
3. **互联网声音是必写维度。** 查 X / LunarCrush 主导率 / AltIndex cashtag。有数字就写进注意力节，并拿来对照市值和成交。没有就标明未披露，不编帖数。过期 cashtag 不能和当日样本混比。热度对短线币价是真变量，不能因为「不是基本面」删掉。
4. 禁止套话：「定价厚，链上锁仓只解释一部分」「能核的规模」「只对上面能核的数字负责」「按赛道给底，不编功能进度」「迷因资产额外下调」「而不是社交媒体热度」。
5. 在 `/tmp/drlabs-live/research/<ticker>/` 新建 `report.md` + `report.{en,ja,ko,fr,es,ru}.md`。
6. **七语块结构必须一致**（标题、段落、表、列表、图的数量与顺序相同）。
7. **表格单元格只保留中英。**
8. 生成图表后拷到 `assets/<ticker>/` 与 `public/research/<ticker>/`。
9. 跑 `python3 /workspace/scripts/i18n_build.py`。
10. 推送 GitHub Pages 的 `main`，再同步预览。

章节没有固定顺序。日更生成器（`desk_analyst.py`）按发现的显著性排列维度章节；手写时也一样：

- 开头：研究结论，第一行写发布日期（澳洲珀斯时间）和数据快照时刻，要有判断，不是复述快照。
- 中间：数据快照表，加上市场结构、代币与供给、链上使用、估值与同行、叙事、KOL 视角里有数据的那几节，按这一个票最重要的事排序。没有数据的维度直接省略。
- 结尾：催化与风险（含什么会改变看法）、买入评分表与评分标准、数据来源、免责声明（含「仅供参考，投资要理性」）。
